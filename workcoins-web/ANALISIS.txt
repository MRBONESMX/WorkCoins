3. ELEMENTOS COMPARTIDOS
- Marca WorkCoins UNI y tipografía Arial disponible sin conexión.
- Menú, encabezado, perfil y pie uniformes para cada rol.
- Tarjetas blancas, fondo claro, naranja, etiquetas y franjas de información.
- Clases sencillas en español y una hoja CSS externa.
- Enlaces de regreso con destinos específicos, no dependientes del historial.
- Avisos que identifican las vistas como ejemplos y los saldos como iniciales.

4. FLUJOS
Cliente: acceso > panel > nueva oferta > detalle > propuestas > evaluación >
  proyecto activo > proyecto finalizado > listado de proyectos.
Freelancer: acceso > panel > explorador > detalle > propuesta > confirmación >
  proyectos; desde la cabecera también puede consultar ganancias y coins.
Los formularios abren ejemplos fijos y no envían sus campos a un servidor.
Los resúmenes secundarios usan details; no remiten al expediente de otra persona.

5. INCONSISTENCIAS OBSERVADAS Y DECISIONES
- Varias pantallas del cliente tenían una etiqueta de freelancer: se separaron
  cabeceras y enlaces por rol.
- El listado de proyectos del freelancer mostraba datos del cliente en la
  cabecera: ahora conserva el perfil de Sofía.
- El dashboard del cliente combinaba 640 y 650 coins: las cabeceras de esta
  maqueta se identifican como saldos iniciales. Las proyecciones se etiquetan.
- El costo y los límites de los tramos cambiaban entre vistas: se unificaron
  en 1-10 = 10, 11-25 = 20, 26-30 = 35 coins, tomando la creación de oferta
  como criterio del ejemplo. No se presenta como una regla real del servicio.
- Las cifras de los históricos variaban: se mantuvo 650 + 400 = 1,050 USD.
- El prototipo decía enviado/pagado: aquí se explica que se visita un ejemplo,
  sin afirmar que se procesó un envío, un contrato o un pago.
- Los botones de compra llevan a una explicación de la maqueta.
- Recuperación, registro y descargas de archivos originales no disponibles
  se explican sin inventar un sistema o un documento inexistente.
- No se verificaron las conexiones internas del modo prototipo de Figma.
  El flujo implementado se reconstruyó por contenido y propósito de las pantallas.

6. NIVEL DEL CURSO Y MOBILE FIRST
Se utilizan encabezados, párrafos, listas, enlaces, tablas, formularios, label,
input, select, textarea, detalles HTML, header, nav, main, article, aside y footer.
Flexbox y @media ya aparecen en Cafeteria y Diseño responsivo.
No se usa una tabla para organizar el diseño general de una página.
El CSS empieza en una columna para celular, a 650 px reorganiza resúmenes y
datos, y a 1000 px muestra columnas y navegación de escritorio.
Las tablas se desplazan dentro de su contenedor y las imágenes son flexibles.
No hay dependencias externas. El filtro y la elección del panel son JavaScript
básico separado, sin almacenamiento ni procesamiento del formulario.

7. ALCANCE Y RECURSOS
Las pantallas de escritorio y las variantes de Figma se tomaron como referencia visual.
Para la versión móvil, se implementó una maquetación responsiva Mobile First mediante Flexbox y consultas de medios (@media) a 650 px y 1000 px.
En lugar de las imágenes de muestra del lienzo de Figma que no se encontraban exportadas, se incorporaron fotografías y recursos visuales locales que corresponden al contexto universitario de los perfiles (Carlos, Sofía y candidatos de diseño), así como capturas y bocetos de wireframes e interfaces para los proyectos.
Todos los recursos están guardados localmente en imagenes/ para asegurar autonomía total sin requerir conexión a internet.
